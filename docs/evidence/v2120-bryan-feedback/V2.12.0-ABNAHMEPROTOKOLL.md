## 6. DIMENSIONEN-ABDECKUNG
1. **Datenmengen:** 23 Mitglieder; 12 Brace-Teams (UT-V12-10); 2-Wochen-Matrix (UT) und 7-Wochen-Seed (5 Wochen 25m-Spalten wegen Brace-Wochen — fachlich korrekt); leere Race-Typen (UT-V12-05: butterfly ohne Events).
2. **Konfigurationen:** ordinary/25m_brace/50m_brace × 75m/back/breast/fly/medley im Seeder; Y/N/Back/Breast/Free-Entries; Jahr-Selektor (availableYears).
3. **Berechnungen:** Matrix-Zellen == Event-Pointscore (46 Zellen, UT-V12-03); Report-2-Totals == Season-Standings (UT-V12-07); Breaker-Count nur Reduktionen (UT-V12-14/16); Amount = Season-Start − Current inkl. negativem Fall (UT-V12-16: −1).
4. **Display:** Select-All→Y (UI-01); Tap-Placing-Badges (UI-02/03); Grid 3 Spalten (UI-04); 3 Hauptreport-Tabs + alle Mitglieder (UI-05); TOTAL-Spalte (UI-06); Count+Amount (UI-07); 0-Punkte-Brace-Zeile (UI-08); Start/Net/Variance/BREAK/manueller Platz im Report (UI-09).
5. **Workflows:** kompletter Event-Zyklus per API (Setup→Heats→Zeiten→Rank→Finalize→Complete) in Unit+Browser-Fixtures; Tap → Untap → Clear; Seeder-Wiederholungslauf (Skip-Pfad); manuelles PB-Senken/Heben/No-Op.
6. **Edge Cases:** PB-Erhöhung zählt nicht (UT-V12-16); No-Op-PUT erzeugt keine Log-Zeilen (UT-V12-17 via Konstanz); Race-Typ ohne Events (UT-V12-05); Mitglied löschen mit Punkten (UT-V12-21, vorher FK-Crash); nicht-podium Brace-Team (UT-V12-11).
